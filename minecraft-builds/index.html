Publishing setup

Point the archive at a GitHub repository. When you publish, screenshots and data/builds.json are committed there, and GitHub Pages serves them to everyone.

owner/repo — create it on GitHub first.

Needs Contents: Read and write for that repository. It stays in this browser and is never saved into the site files.

Five minutes

Put the archive online

  1. 1. Create the repository

    On GitHub, make a new public repository, for example minecraft-builds. Don't add a README — you'll upload this folder as-is.

  2. 2. Upload the site

    Open the repository, choose Add file → Upload files, then drag in everything from this folder (index.html, styles.css, app.js, data, and the rest). Commit.

  3. 3. Turn on GitHub Pages

    In the repository go to Settings → Pages. Under Source pick Deploy from a branch, branch main, folder / (root). Save.

    After a minute your archive is live at https://yourname.github.io/minecraft-builds/.

  4. 4. Let the site publish for you

    Create a fine-grained token at github.com/settings/tokens?type=beta for just that repository with Contents: Read and write. Paste it into Publish → Publishing setup here. Now “Publish to GitHub” uploads new screenshots and build data straight to the repo.

New screenshots are resized in the browser before upload, so a page full of builds still stays light. Publishing usually appears on the live site within a minute.
